# 创作流程说明

记录从一句需求到两个可交付页面的完整过程：每个阶段做了什么、为什么这样决定、在哪里返工。

## 阶段 0 · 参考研究与取舍

先看同类实现，再决定不做什么。

| 参考 | 取什么 | 不取什么 |
| --- | --- | --- |
| sukikeeling/gesture-blooming-flower | 静态部署 + MediaPipe + Three.js 的最小可用链路 | 单一形态插值、绿黑配色 |
| FIQTOR/particle-handtracker | 无摄像头时用滑块降级的产品思路 | — |
| ppongtong/gesture-particle | 弹簧动力学与手势稳定化 | — |
| longzheng268/Gesture-Controlled-Particles | 粒子从形态散开成场的状态组织方式 | — |

参考项目只用于比较交互架构，实现代码全部重写。用户提供的参考包用于了解同类实现并取得本地 Hand Landmarker 模型，其玻璃拟态界面与双形态插值未沿用。

**产出**：一张技术选型清单——零构建（原生 ESM + import map 不需要打包器）、Three.js r180、MediaPipe Tasks Vision 1.2.0、GSAP 仅用于界面入场。

## 阶段 1 · 花信：把「聚散」做出来

**1.1 形态先行，先做静帧。** 不接手势，先用固定开合值把三个形态各自调到能看：花苞的螺旋包裹、四层花瓣的仰角与下垂、星场的分布。此时的验收标准是「单帧截图像一张作品」。

**1.2 三套位置进同一个缓冲。** 每个粒子存 `aBud`（花苞）、`aOpen`（花冠）、`aStar`（星场）与 `aScatter` 权重、`aScatterDelay` 延迟；顶点着色器按 `uBloom` 在两段之间混合，再按散射权重混入星场。**决定**：不用三段动画串接，因为任何中间值都必须是完整形态。

**1.3 手势链路。** 开合度＝四指「指尖到手腕 / 指节到手腕」比值的平均，再与拇指加权——比值不受手掌大小、镜头远近、手腕旋转影响。信号经 One Euro Filter，再由场景中的临界阻尼弹簧（`k=210, c=29`）追踪，约 0.2 秒到位且不过冲。检测独立于渲染，上限 25fps；手离开画面保持当前形态。

**1.4 降级路径。** 摄像头拒绝 / 无设备 / 非 HTTPS / 模型失败，四条路径统一回到手动模式；无 WebGL 2 显示静态线稿与说明；`file://` 提示改用本地服务器。

**1.5 返工：数字滑杆（当日追加）。** 初版固定 12,950 粒子。加入数量控件后暴露出一串问题：重建几何会重置开合、拖动时反复分配导致卡顿、移动端范围与桌面相同导致低端机发热。逐一处理为——重建时保留 `uBloom` 与配色、90ms 防抖、桌面 4,000–30,000 / 手机 3,000–16,000 分档。

**阶段产出**：`versions/rose/` 可独立运行，控制台零报错，五个视口（1440 / 1024 / 834 / 768 / 390）通过。

## 阶段 2 · 莲境：把预算全部压给花冠

**决定**：第二朵花不做「又一个会散开的花」，而是取消花茎、叶片与星场，把所有视觉预算给花冠本身，靠密度与光色立住。

**2.1 粒子分配表先定，再写几何。** 12 / 10 / 8 / 6 四层花瓣 + 莲蓬 2,400 + 花丝 1,400 + 芯光 500，默认总量 80,000。分配表写在 BRIEF 里，几何代码按表生成，避免「先写再数」。

**2.2 花瓣曲面。** 极坐标参数面：`s` 沿花瓣长度、`u` 横向；宽度按 `sin(π·s^0.58)^0.58` 收成尖端；高度 `rise·s^1.18 - droop·s^3.4`，叠加 `u²` 杯形项。

**2.3 花苞不重算，只重映射。** 合拢时把所有粒子的 `s` 重映射到螺旋尖顶轮廓，点径缩到 55%，避免 8 万点堆成白色实体。

**2.4 配色切换不重建几何。** 每个粒子预存三套颜色，切换只改 `uPalette`（0→1→2），着色器在相邻两套间 `smoothstep` 插值；界面强调色跟随 `body[data-palette]`。

**2.5 跟随。** 手掌位置直接映射到整组 `x/y` 平移（±0.6 / ±0.4 世界单位），不做粒子级弹簧——8 万粒子下逐点弹簧必然抖动。

**阶段产出**：`versions/lotus/` 可独立运行；80,000 粒子桌面流畅，120,000 不报错；三套配色亮度一致。

## 阶段 3 · 入口与文档

**3.1 入口页。** 两张卡片，各自一段命题与参数说明，点击进入对应版本。入口页不加载 Three.js，保持轻量。

**3.2 文档分层。** 每个版本保留 `README.md`（使用与实现）与 `creative/BRIEF.md`（该版本的创作思路与验收标准）；仓库层再补创作思路、创作流程、创作指导、版本管理四篇，避免把版本细节堆进根 README。

**3.3 版本化。** 把过程固化成两个版本：`v1.0.0` 只含花信与基础工程，`v2.0.0` 加入莲境、入口页与文档体系。见 [版本管理与发布](04-版本管理与发布.md)。

## 返工与踩坑记录

真实项目中花时间最多的不是新功能，而是这些：

1. **入场动画卡在 opacity 0。** 首帧编译着色器产生长帧，GSAP 的 `lagSmoothing` 触发跳帧补偿，把入场的时间轴跳过。修复：`gsap.ticker.lagSmoothing(0)`，并加 2.6 秒兜底。
2. **取景框跑到左上角。** `.camera` 漏写 `position:absolute`，在流式布局里被顶飞。修复：显式定位并锁定层级。
3. **自适应 DPR 被重置。** 每次 `layout()` 都重算像素比，导致切窗口后清晰度回弹。修复：把 DPR 决策抽成独立函数，只在尺寸变化时调用。
4. **整朵花发雾。** 花瓣边缘柔化半径过大，13,000 个粒子叠成一片雾。修复：边缘聚集采样 + 轻微提亮，柔化只作用于 sprite alpha 而非位置。
5. **数量滑杆打断观看。** 重建几何重置开合与配色。修复：重建时读回当前 `uBloom` 与 `uPalette`，重建后立即写回。
6. **摄像头影像出现在界面。** 初版可见取景画面，破坏纯黑视觉且涉及隐私。修复：视频层 `opacity:0`，只绘制骨架。

## 复盘

**有效**：先把静帧调到能看，再接管交互；把失败路径当成一等需求而非补丁；把参数写进文档再写进代码。

**代价高**：为「粒子数量可调」付出的返工远超预期——它牵动几何重建、状态保持、设备分档三条线。如果重来，会先定分档策略再写控件。

**未做**：音频、录制、多花同屏、GLB 资产。它们都会稀释「一只手 → 一朵花」这条主线。
