## 1. 需求

核心只有一句话：**用一只手的开合，控制一朵由 GPU 粒子构成的花。**

在此之上的约束条件：

- 零构建：不引入打包器与 npm 依赖，浏览器直接跑原生 ESM。
- 隐私：摄像头画面不显示、不上传、不录制。
- 可用性：没有摄像头权限时，页面必须完整可用。
- 形态：至少两个版本，共享同一套交互骨架，但视觉命题不同。

需求没有指定技术栈与视觉风格，这部分由实现阶段决定，并在文末的决策记录中逐条留痕。

## 2. 第一版：花信

### 2.1 技术选型

浏览器端粒子渲染有两条路：CSS/Canvas 2D 与 WebGL。13,000 个粒子在 2D 上逐帧重绘必然掉帧，因此选 Three.js + 自定义着色器。手势用 MediaPipe Tasks Vision 的手部关键点（21 点），模型与 WASM 下载到本地 `vendor/`、`models/`，运行时不请求第三方 CDN。

选型结论：Three.js r180、MediaPipe Tasks Vision 1.2.0、GSAP 3.15（仅用于界面入场与状态文字过渡）。

### 2.2 形态：三个停靠点

命题被拆成一条只有三个停靠点的时间线：**花苞 → 花冠 → 星野**。核心句「聚是一朵花，散是漫天星」。

实现上的关键决定是「不做三段动画串接」：每个粒子同时存三套位置（`aBud`、`aOpen`、`aStar`），顶点着色器按开合度 `uBloom` 与散射权重连续混合。这样任何中间值停下来都是一帧完整画面，而不是过渡态。

花瓣是极坐标参数面：`s` 沿花瓣长度、`u` 横向，宽度轮廓基部收窄、上部保持、尖端收口；四层使用不同长度、仰角与下垂量。花茎、两片叶子、花萼、花蕊一并进同一个 `BufferGeometry`，全花一次 draw call。

### 2.3 手势

第一版试过直接取「指尖到手腕的距离」，问题很明显：手掌离镜头远近、手腕倾斜都会改变数值。改为比值法——四指「指尖到手腕 / 指节到手腕」的平均，再与拇指加权。比值对手掌大小、镜头距离、手腕旋转都不敏感。

信号链：原始开合度 → One Euro Filter（慢速抑抖、快速低延迟）→ 场景内临界阻尼弹簧（`k=210, c=29`，约 0.2 秒到位且不过冲）。检测独立于渲染，上限 25fps，手离开画面时保持当前形态。

### 2.4 降级

把失败路径当一等需求做，而不是出错再补：

- 无 WebGL 2 → 静态线稿 + 文字说明；
- 摄像头拒绝 / 无设备 / 非安全上下文 → 自动回手动模式，画布不中断；
- `file://` 打开 → 提示改用本地服务器；
- `prefers-reduced-motion` → 关闭入场与呼吸；
- 标签页隐藏 → 暂停渲染。

### 2.5 首版验收

五个视口（1440 / 1024 / 834 / 768 / 390）通过，控制台零报错，请求全部同源，桌面 60fps 量级、推理 5–6ms。首版默认 12,950 粒子（显示取整为 13,000）。

## 3. 第一轮修改意见

第一版交付后收到两条修改意见，都在当天 19:30 前后落地。

### 3.1 粒子数量要能实时调

原先粒子数是编译期常量。加入控件后暴露三个连锁问题：

1. **重建几何会重置观看状态**——开合回到默认值。修复：重建后读回当前 `uBloom` 写回。
2. **拖动时反复分配**——每移动一格重建一次，卡顿明显。修复：90ms 防抖，`change` 事件立即落定。
3. **移动端照搬桌面范围**——低端机发热。修复：桌面 4,000–30,000、手机 3,000–16,000，步进 1,000，默认值分档（桌面 13,000 / 手机 8,000 / 低性能 10,000）。

所有外部传入的数值统一经 `normalizeParticleCount()` 取整并夹取范围，非法值保持上一个有效值。

### 3.2 摄像头画面不要出现在界面里

这是隐私要求，也是视觉要求：真实影像会破坏纯黑画面。处理方式是把视频层 `opacity:0`，取景框里只保留 21 点骨架与静态手形提示。画面仍然参与检测，但从不出现在视觉层。

### 3.3 修改后验收

- 默认 12,999 粒子，4,000 → 3,999，30,000 → 30,000，连续拖动无报错；
- 开合值在重建后保持不变（实测 0.62 不变）；
- 手机两个滑块无重叠，横向无溢出；
- 静态检查 0 FAIL。

## 4. 第二版：莲境

第二版没有沿用「又能散开的花」这个思路，而是反着走：取消花茎、叶片与星场，把所有视觉预算压给花冠本身，靠密度与光色立住。

- **粒子分配先定表**：12 / 10 / 8 / 6 四层花瓣 + 莲蓬 2,400 + 花丝 1,400 + 芯光 500，默认 80,000。
- **花瓣曲面**：宽度按 `sin(π·s^0.58)^0.58` 收成尖端，高度 `rise·s^1.18 - droop·s^3.4` 叠加 `u²` 杯形项。
- **花苞不重算**：把 `s` 重映射到螺旋尖顶轮廓，点径缩到 55%，避免八万点堆成白色实体。
- **配色不重建几何**：每个粒子预存三套颜色，切换只改 `uPalette`（0→1→2）并做 `smoothstep` 插值。
- **跟随不做逐点物理**：手掌位置直接映射为整组平移（±0.6 / ±0.4 世界单位），8 万粒子下逐点弹簧必然抖动。

随后补齐整站入口页 `index.html` 与 `assets/landing.css`，入口不加载 Three.js，保持轻量。

## 6. 仓库整理与运行时入库（v2.1.0）

首轮发布时，`vendor/`（Three.js、MediaPipe、GSAP）与 `models/`（手部模型）被 `.gitignore` 排除，由构建脚本在 CI 中下载。这在体积上是对的，但代价是仓库本身不完整：clone 下来无法直接打开，必须联网执行脚本。

本次收尾做了四件事：

1. **取消排除**：从 `.gitignore` 移除 `vendor/`、`models/`，运行时资源正式入库（约 52MB，其中三个 WASM 各 12.9–14.5MB、模型 7.8MB）。
2. **补齐文档**：新增本开发日志；更新 README 的目录结构与运行说明（仓库内已含运行时，`fetch-assets.sh` 变为可选的重建工具）。
3. **结构整理**：根目录只保留入口页、README、CHANGELOG、CREDITS、`.gitignore`、`.nojekyll`；代码按 `versions/<flower>/`、文档按 `docs/`、依赖按 `vendor/`、模型按 `models/`、脚本按 `scripts/` 分置。压缩包、bundle、缓存、日志与临时文件不入库。
4. **完整性验证**：从仓库重新下载一份到新目录，脱离原工作区独立启动并打开两个页面，确认运行时资源路径全部自洽。

## 7. 决策记录

| 决策 | 选择 | 放弃的方案 | 理由 |
| --- | --- | --- | --- |
| 渲染 | Three.js + 自定义着色器 | Canvas 2D、CSS 粒子 | 万级粒子 2D 必然掉帧 |
| 形态插值 | 顶点着色器内混合三套位置 | 三段动画串接、CPU 逐帧插值 | 中间值必须是完整形态，且不能占用主线程 |
| 开合度 | 指尖/指节比值 | 绝对距离、手掌包围盒 | 不受手掌大小、距离、旋转影响 |
| 平滑 | One Euro + 临界阻尼弹簧 | 单层低通、线性插值 | 兼顾抑抖与低延迟，且不过冲 |
| 数量调节 | 重建 BufferGeometry + 释放旧缓冲 | 预留最大缓冲、隐藏多余粒子 | 显存占用随实际数量走 |
| 莲境配色 | 预存三套 + `uPalette` 插值 | 切换时重算顶点色 | 8 万粒子重建会明显卡顿 |
| 跟随 | 整组平移 | 逐粒子弹簧 | 高密度下逐点物理必然抖动 |
| 摄像头画面 | 不显示，只画骨架 | 小窗预览 | 隐私与纯黑视觉 |
| 运行时资源 | 本地自托管 | CDN 引用 | 离线可用、版本可控 |
| 依赖入库 | v2.1.0 起提交 `vendor/`、`models/` | 永远靠脚本下载 | 仓库需可独立运行 |
