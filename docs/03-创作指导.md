# 创作指导

面向要在这个仓库里继续做花的人。读完应能独立加一朵新花，且不破坏既有的手势、降级与性能约定。

## 1. 本地起跑

```bash
git clone <repo>
cd particle-flora
python -m http.server 8080
```

- 花信：<http://localhost:8080/versions/rose/>
- 莲境：<http://localhost:8080/versions/lotus/>

`vendor/` 与 `models/`（约 52MB）自 `v2.1.0` 起随仓库提交，克隆后无需再下载即可运行。`scripts/fetch-assets.sh` 仅在资源缺失或需要重建时使用，脚本会跳过已存在的文件。摄像头只在 `localhost` 或 HTTPS 下可用；`file://` 打开会给出提示而不是静默失败。

## 2. 架构

```
index.html                入口页（不加载 Three.js）
assets/landing.css        入口视觉
versions/<flower>/
  index.html              页面结构（canvas + 控制面板 + 兜底线稿）
  assets/style.css        该版本的视觉令牌与响应式
  src/main.js             交互、状态机、控件、降级判定
  src/scene.js            Three.js 场景、着色器、渲染循环
  src/<flower>.js         粒子几何（唯一与"这朵花长什么样"强相关的文件）
  src/gesture.js          MediaPipe 手部检测 → 开合度
  README.md               使用与实现说明
  creative/BRIEF.md       该版本的创作思路与验收标准
```

两个版本刻意保持同一文件划分，差别只在 `<flower>.js` 与着色器细节。新增版本应沿用这套划分，而不是发明新结构。

### 模块职责

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| `main.js` | DOM 绑定、开合状态、控件、手动优先计时、能力检测与降级分支 | 任何几何计算与着色器 |
| `scene.js` | 相机、材质、uniform 更新、渲染循环、DPR 与帧率降级 | 手势语义 |
| `<flower>.js` | 生成 `BufferGeometry`：位置、颜色、尺寸、延迟、散射权重 | 交互与渲染顺序 |
| `gesture.js` | 摄像头、MediaPipe、21 点 → 开合度（0–1） | 场景与动画 |

### 数据流

```
手部 21 点 ──measureOpenness()──► 原始开合度
        │
        ├─ One Euro Filter（去抖，快速时低延迟）
        │
        └─ 临界阻尼弹簧 k=210, c=29（约 0.2s 到位，不过冲）
                 │
                 ▼
            uBloom (0–1) ──► 顶点着色器混合 花苞 / 花冠 (/ 星场)
                 ▲
   滑块 / 拖拽 / 键盘 ──┘   手动操作后 2.4s 内手势不抢权
```

## 3. 着色器接口

新增版本时，**复用同名 uniform**，让 `main.js` 的控件与 `scene.js` 的更新逻辑可以直接照搬。

### 花信

| uniform | 含义 |
| --- | --- |
| `uBloom` | 开合度 0–1 |
| `uScatter` | 星场总体散射强度 |
| `uSpread` | 星场按视口比例的铺开尺度 |
| `uPointer` | 指针/手掌位置，用于视差 |
| `uMotion` | 入场与呼吸的时间量 |
| `uTime` | 秒级时间 |
| `uFocal` | 透视焦距，用于点径衰减 |

顶点属性：`aBud` `aOpen` `aStar`（三套位置）、`aScatter` `aScatterDelay`（散射权重与延迟）、`aColor` `aStarColor`（花瓣与星场颜色）、`aSize` `aEdge` `aKind` `aSeed` `aDelay`（尺寸、边缘、类型、随机种子、逐粒子延迟）。

### 莲境

| uniform | 含义 |
| --- | --- |
| `uBloom` | 开合度 0–1 |
| `uPalette` | 配色插值 0→1→2 |
| `uPointer` | 整花平移 |
| `uMotion` | 入场 |
| `uTime` | 秒级时间 |
| `uFocal` | 点径衰减 |

顶点属性：`aBud` `aOpen`（两套位置）、`aColorA` `aColorB` `aColorC`（三套配色）、`aSize` `aEdge` `aSeed`。

**共同约定**：一个 `BufferGeometry`、一个 `Points`、一次 draw call；位置插值全部在 GPU；CPU 每帧只写 uniform。

## 4. 新增一朵花的步骤

以新增「versions/iris/」为例：

1. **写 BRIEF。** 先回答三个问题：这朵花的命题是什么、它和已有两朵的对立面在哪、开合的三段（或两段）分别是什么形态。没有这一步不要写代码。
2. **定粒子分配表。** 列出花瓣层数、每层瓣数与粒子数、附属结构（花心、花蕊、茎、叶）与总量。默认值按中端设备定，上限只作尝试空间。
3. **复制目录。** `cp -R versions/rose versions/iris`，改 `title`、状态词、配色令牌，把 `src/flower.js` 换成 `src/iris.js`。
4. **先做静帧。** 固定 `uBloom` 为 0 / 0.5 / 1，把三个形态各自调到能看，再接通滑块。
5. **复用 gesture.js。** 除非手势语义要变，否则不要改它；开合度算法与滤波参数经过验证，改动会同时影响所有版本。
6. **接入降级。** 无 WebGL 的静态线稿、摄像头失败的手动模式、`prefers-reduced-motion`、标签页隐藏暂停——四条都要有，缺一不可。
7. **补文档。** 版本 `README.md`（操作、形态表、实现要点）与 `creative/BRIEF.md`（命题、视觉、验收标准），并在根 `README.md` 的版本表加一行。
8. **过检查清单**（见第 8 节），再提交。

**新增目录必须放在 `versions/<name>/` 下。** 页面里的依赖路径是 `../../vendor/...` 与 `../../models/...`，改动层级会直接断链。

## 5. 参数调校

| 参数 | 位置 | 花信 | 莲境 | 调整影响 |
| --- | --- | --- | --- | --- |
| 默认粒子 | `main.js` | 13,000（手机 8,000 / 低端 10,000） | 80,000（手机 40,000 / 低端 50,000） | 观感密度与发热 |
| 范围 | `main.js` | 4,000–30,000（手机 3,000–16,000） | 20,000–120,000（手机 20,000–60,000） | 上限过高会拖垮中端机 |
| 步进 | `main.js` | 1,000 | 5,000 | 拖动时重建频率 |
| 弹簧 | `scene.js` | `k=210, c=29` | 同 | 过硬显机械，过软显迟钝 |
| 手动优先 | `main.js` | 2.4s | 2.4s | 太短会抢权，太长会失灵 |
| 检测帧率 | `gesture.js` | ≤25fps | ≤25fps | 与渲染解耦，不必跟随刷新率 |
| 点径 | 着色器 | 按 `uFocal` 衰减 | 同，且有上限 | 过大糊成一片，过小失去体积 |
| 像素比 | `scene.js` | 0.2–2.4 夹取 | 同 | 高分屏清晰度与填充率 |

改参数后必须同时更新版本 `README.md` 与 `BRIEF.md` 中的数字——文档与实现不一致比没有文档更糟。

## 6. 性能预算

- 桌面目标 60fps，移动端不低于 45fps。
- 帧率持续低于 44 三秒以上，降低像素比；恢复后不自动升回（避免抖动）。花信与莲境共用该策略。
- 粒子数变化时重建 `BufferGeometry` 并立即 `dispose()` 旧几何；重建用 90ms 防抖，并保留 `uBloom` 与配色。
- 不为 8 万粒子做逐点 CPU 弹簧。整组平移、整组缩放可以，逐点物理不行。
- 不使用后期 bloom。亮度靠粒子叠加，不靠全屏辉光。

## 7. 视觉与隐私规范

- 背景只有两种合法值：暖近黑 `#130b0c`、纯黑 `#030203`。不加渐变与装饰纹理。
- 花瓣颜色只从既定色板取；莲境三套配色共用同一亮度级，不允许某一套明显更暗或更荧光。
- 界面控件扁平，不使用玻璃拟态、CSS 渐变、大面积阴影、圆角卡片。
- 字体只用系统字体；宋体标题、黑体正文。
- 摄像头画面不得显示、不得上传、不得录制；取景框只画骨架与静态手形。
- 所有图形程序化生成或内联 SVG，不引入外部图片与 3D 资产。

## 8. 提交前检查清单

- [ ] 三个（或两个）形态静帧都能独立成立
- [ ] 任意中间开合值不塌陷、不出现平面圆盘
- [ ] 拒绝摄像头、关闭设备、`file://`、禁用 WebGL 四条降级路径均可用
- [ ] 数量滑块拖动不闪断、不重置开合与配色
- [ ] 390px 宽无横向溢出，键盘可完成主要操作
- [ ] `prefers-reduced-motion` 生效，标签页隐藏时暂停
- [ ] 控制台零报错，无跨源请求（除本地 `vendor/`、`models/`）
- [ ] README 与 BRIEF 的数字与代码一致
- [ ] 根 README 版本表已更新

## 9. 部署

仓库自带 `.github/workflows/pages.yml`：检出 → 校验运行资源（缺失时才执行 `scripts/fetch-assets.sh`）→ 把 `index.html`、`assets/`、`versions/`、`scripts/`、`docs/`、`vendor/`、`models/`、`.nojekyll` 汇总到 `_site` → 上传并发布到 GitHub Pages。

- 推送 `main` 或手动触发 workflow 即部署。
- 首次部署需要在仓库 **Settings → Pages → Build and deployment** 把 Source 设为 **GitHub Actions**。CI 的 `GITHUB_TOKEN` 无权创建 Pages 站点，`configure-pages` 的 `enablement` 在未启用时会失败。
- 页面依赖 `versions/<name>/` 层级，不要修改 `_site` 的目录结构。

## 10. 常见故障

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面白屏、控制台 404 `three.module.js` | 资源缺失（浅克隆或手工拷贝漏了 `vendor/`） | 执行 `scripts/fetch-assets.sh` 后刷新 |
| 摄像头按钮无反应 | 非 HTTPS / 非 localhost | 用本地服务器或线上地址打开 |
| 花瓣糊成一片光 | 点径过大或边缘柔化过强 | 降 `aSize` 上限，柔化只作用于 alpha |
| 入场动画不出现 | `lagSmoothing` 跳帧 | 保持 `gsap.ticker.lagSmoothing(0)` |
| 切窗口后变模糊 | DPR 被 `layout()` 重置 | DPR 只在尺寸变化时决策 |
| 数量拖动卡顿 | 未防抖、旧几何未释放 | 90ms 防抖 + `dispose()` |
