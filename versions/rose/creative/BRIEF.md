# 花信 · 创作思路与方法指导

## 1. 命题

「花信」不是一朵静止的花，而是一条只有三个停靠点的时间线：

> 花苞 → 花冠 → 星野。

核心句是「聚是一朵花，散是漫天星」。因此所有粒子必须能在三种形态之间连续移动，而不是三段动画拼接。任何时刻停下，画面都应该是一个完整的形态。

## 2. 视觉方向

- 暖近黑画布 `#130b0c`，让粉色粒子自己发光，不使用后期辉光或霓虹。
- 单朵花，一根花茎，两片叶子，不添加第二束花、不堆装饰。
- 四层花瓣：外层低垂外翻，中层抬起，内层直立合抱，花心暖白。
- 配色只取粉红、浅桃粉、玫瑰红、暖白；界面保持扁平，不使用玻璃拟态、CSS 渐变或大面积阴影。
- 字体：宋体承担标题与状态词，系统黑体承担操作与说明。

## 3. 形态与粒子映射

每个粒子携带三套位置和一组延迟：

1. **花苞**：花瓣绕轴螺旋包裹，基部收窄、顶端收尖；粒子的尺寸在合拢时缩小，避免高密度叠成一块实心色块。
2. **花冠**：极坐标参数曲面。`s` 沿花瓣长度、`u` 横向铺开；宽度轮廓在基部收窄、上部保持宽、尖端收口；边缘沿 `u²` 抬起形成杯状。四层使用不同长度、仰角与下垂量。
3. **星场**：外层 100%、中层 25% 的粒子拥有散射权重。星场位置是归一化坐标，运行时按视口 `uSpread` 缩放，因此在任意比例屏幕上都能覆盖画布；少量粒子留在花心附近，让散开过程连续。

顶点着色器只做三件事：按开合度混合花苞/花冠、按散射权重混合星场、给每个粒子加极轻的呼吸。没有更换模型，也没有逐帧重算 CPU 位置。

## 4. 手势方法

- 开合度＝四指「指尖到手腕 / 指节到手腕」比值的平均，再与拇指加权。比值不受手掌大小、镜头远近和手腕旋转影响。
- One Euro Filter 做第一层平滑：慢速时抑抖，快速时降低延迟。
- 场景内用临界阻尼弹簧追踪目标值，约 0.2 秒到位且不过冲。
- 摄像头检测独立于渲染，最多 25fps；手离开画面时保持当前形态。
- 手动操作优先：拖动滑块或点击形态后的 2.4 秒内，手势不抢回控制权。

## 5. 实现取舍

- 三形态必须在 GPU 内完成，否则 13,000 粒子逐帧在 CPU 上插值会拖慢手势响应。
- 粒子上限不做「越多越好」：默认 13,000，按视口和硬件降级；数量控件允许 4,000–30,000 实时切换。
- 不使用后期 bloom，避免霓虹感；亮度来自粒子 sprite 的柔和 alpha 与重叠，而不是全屏发光。
- 摄像头画面不进入界面，只保留骨架线条与手形提示，减少隐私与视觉干扰。

## 6. 验收标准

- 握拳时能清楚辨认花茎、两片叶子和完整花苞。
- 中间任意开合值都应有前后层次，不能只剩一个平面圆盘。
- 全开时星场覆盖画布，但花心与内层花瓣仍然可辨。
- 拖动数量时画面不闪断、不重置开合。
- 摄像头不可用时画布与手动控制照常工作。
- 手机 390px 宽无横向溢出，键盘可完成所有主要操作。
