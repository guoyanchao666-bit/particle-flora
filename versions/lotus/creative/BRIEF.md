# 莲境 · 创作思路与方法指导

## 1. 命题

一朵由八万颗发光粒子组成的莲花，只有两件事在变：**开合**与**位置**。

- 手掌完全张开：所有花瓣展开，粒子饱满，边缘有柔和光晕。
- 手掌收拢：花瓣向内层层合拢，最终成为紧实的尖顶花苞。
- 手掌移动：整朵莲花同步平移，形态本身不变。

与「花信」不同，这一版没有花茎、叶片或星场，所有视觉预算都留给花冠本身。

## 2. 视觉方向

- 背景为纯黑 `#030203`，不放渐变、不放装饰，让粒子的亮度成为唯一层次。
- 花瓣是尖瓣，不是圆瓣：基部窄、腹部宽、尖端收成一点；四层从外向内逐层抬高。
- 花心比花瓣更深，靠一小簇暖色芯光形成焦点，避免整朵花均匀发白。
- 三套配色：粉紫（默认）、蓝紫、暖金。每套使用同一组亮度级：深色基部 → 中间色 → 边缘高光。
- 界面沿用「花信」的宋体标题、系统黑体操作文字与平面控件，只把强调色改为随配色切换的紫色/金色。

## 3. 八万粒子的分配

默认 80,000：

| 部分 | 数量 |
| --- | --- |
| 外圈 12 瓣 | 31,200 |
| 中圈 10 瓣 | 23,000 |
| 内圈 8 瓣 | 15,200 |
| 芯圈 6 瓣 | 6,300 |
| 莲蓬 | 2,400 |
| 花丝 | 1,400 |
| 暖色芯光 | 500 |

数量滑块把同一比例放大或缩小到 20,000–120,000；几何重建后仍保留当前开合和配色。

## 4. 花瓣曲面与花苞

- 花瓣用极坐标参数面：`s` 是长度方向，`u` 是横向；横向宽度按 `sin(π·s^0.58)^0.58` 收成尖端。
- 纵向高度由 `rise·s^1.18 - droop·s^3.4` 控制，再叠加 `u²` 的杯形项，让花瓣边缘略高于中线。
- 花苞把所有粒子的 `s` 重新映射到一条螺旋包裹的尖顶轮廓，合拢时点径缩小到 55%，避免八万点堆成白色实体。
- 花瓣按外圈到芯圈依次进入缓冲，绘制顺序天然形成前后层次，不依赖深度排序。

## 5. 手势与跟随

- 开合度与「花信」共用同一套比例算法、One Euro Filter 与临界阻尼弹簧。
- 手掌位置直接映射到整组 `x/y` 平移，幅度约 ±0.6 / ±0.4 世界单位；花冠本身不做粒子级弹簧，避免高密度下的抖动。
- 手动操作后 2.4 秒内不抢回控制权。
- 摄像头画面不显示，只画 21 点骨架；失败时停在手动模式。

## 6. 配色切换的实现

每个粒子预存三套颜色。切换时只更新 `uPalette`（0→1→2），着色器在相邻两套之间插值：

```glsl
vec3 col = uPalette < 1.0
  ? mix(colA, colB, smoothstep(0.0, 1.0, uPalette))
  : mix(colB, colC, smoothstep(1.0, 2.0, uPalette));
```

因此切换配色是连续的，不重建 80k 几何，也不丢失开合状态。界面强调色同步跟随 `body[data-palette]`，但按钮、文字与粒子的亮度关系保持一致。

## 7. 性能取舍

- 80k 粒子只用一个 draw call，位置全部在 GPU 内插值，CPU 每帧只更新几个 uniform。
- 数量变化时重建 BufferGeometry，并立即释放旧几何；90ms 防抖避免拖动时反复分配。
- 点径按距离衰减并限制上限；合拢状态点径更小，降低过度绘制。
- 帧率低于 44 持续三秒时降低像素比；手机默认 40,000 粒子。
- 不使用后期 bloom，因为 80k 的密集叠加本身已形成亮心，额外辉光会掩盖花瓣层次。

## 8. 验收标准

- 四种视角下都能数出至少三层花瓣，花苞有尖顶。
- 三个配色亮度一致，没有一套明显更暗或更荧光。
- 80,000 粒子下桌面保持流畅；数量拉到 120,000 不报错。
- 手掌移动时花朵跟随，形态不塌陷、不抖动。
- 手机上花瓣不被裁切，颜色按钮和数量滑块可用。
